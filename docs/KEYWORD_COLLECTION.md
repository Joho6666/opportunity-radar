# 关键词、时效、热度与帖子评分

本轮在 `feat/production-acquisition-loop` 扩展原有收件箱与雷达，不另建采集器或客户库。入口：`/evidence` 的“采集”，或 `/radars/new`；已保存雷达可在详情页“编辑配置”。

## 配置与实际行为

| 配置 | 实际执行 |
|---|---|
| 搜索关键词 | 雷达中的中文/英文逗号、分号、换行可分隔查询；规则回退尊重每个原始查询，不再强加“线上 有偿”。实际提交的查询在详情页可见 |
| 包含词/排除词 | 后端对标题和原文做大小写无关的字面匹配；任意命中/全部命中；排除优先，每组最多20词，每词100字。不是已验证的语义精准搜索 |
| 时间窗口 | 1–720小时；原帖发布时间/来源最近更新时间可选。新客户端默认按原帖发布时间，过滤时间未知；旧雷达保留按来源活动时间、保留未知的兼容默认 |
| 活跃信号 | 不限；窗口内有时间及公开作者；窗口内有时间、作者和累计评论计数。可设最低公开互动量；缺字段不能冒充已通过条件 |
| 最新/热度排序 | 对已取得的单页或雷达运行结果排序；收件箱对已加载证据再排序。不是平台热榜、全平台热搜，也不代表互动发生在窗口内 |
| 获客分/热度分 | 两个独立分数，缺数据为未知或明确中性估算；非买方、已排除、已取消/过期/不适用需求获客分为0。人工状态和A/B/C证据等级独立 |

每次手动只取一页，过滤为空不会自动补抓。返回过期、时间未知、关键词与活跃信号的过滤数量；空页仍保留有效续页。修改条件改变请求指纹及国内会话绑定，旧续页不能混用新条件。同一幂等请求返回原收据，不再次采集。

雷达配置使用新增 `collection_policy` JSONB列持久化。运行先统一筛选，再分类、去重与审核；显式包含词已通过时，自动编译出的自然语言词不能再次将其否决。手动频率不会进入Scheduler，即使历史 `next_run_at` 有值。编辑关键词后清除旧查询计划。

## 分数解释

`EvidenceRecord.ranking`由服务端计算，`kind=prediction`。获客优先级 = 原有七维获客预测 ×70% + 发布时效 ×20% + 热度 ×10%。原有维度为需求明确程度、预算匹配、交付能力、竞争、工作量、紧急程度、证据等级；当前收件箱未传入个性化预算门槛、能力和工时时采用中性分并说明，不冒充真实匹配。热度低权重，不能把广告变成买方。

时效按来源时间衰减，不使用采集时间。超过当前时间5分钟的异常未来时间视为未知。热度对公开点赞/评论/分享等累计量做对数缩放与时间衰减；未知与明确0分开，播放数不作为互动数。累计评论没有评论时间时明确未知。不同平台计量有差异，分数不是校准后的成交概率或真人检测结果。

同帖再次采集只刷新公开互动/作者/来源更新时间，不增加唯一证据，不覆盖人工备注和已核实状态，不用最近采集时间冒充发布时间。原文改变仍进入原有修订与重新复核流程。

## 来源限制与建议

- RSS只读取配置或明确填写的订阅地址，并从返回的前10条/订阅筛选；不是全网搜索。可以先选“V2EX外包”，用“网站，小程序”等包含词筛选，不建议强制评论数（RSS通常不提供）。
- Hacker News适合英文技术需求；GitHub开放Issue只是需求信号，不能当作付款承诺。
- 小红书/抖音现有端点上游固定近一周、知乎近一月；本地窗口只能进一步缩小，不扩展上游范围。真实响应/密钥和分页仍未验证。
- 国内精确端点官方价格尚未核实，真实付费继续关闭。保留已有累计5次/US$0.50/单次US$0.10限制，不因配置/测试/重启恢复额度。
- 未实现跨平台热门接口抓取、账号历史/真人身份核验、完整评论历史或平台实时流。公开作者和累计互动不能证明真人、近期回复或可成交。

建议首次找单：24–72小时、发布时间、未知时间不保留、领域包含词、教程/服务商排除词；先不限互动，不要因为潜在客户零点赞而自动放弃。查看买方分类、原文预算/需求与风险后再人工核实、转入Pipeline。
